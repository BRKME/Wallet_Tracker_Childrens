# Еженедельный риск-отчёт

Второе сообщение в Telegram по воскресеньям (11:00 MSK, через час после
отчёта «план/факт»). Отвечает на вопрос не «сколько денег», а «что может
пойти не так и что с этим делать».

Запуск: `.github/workflows/weekly_risk.yml` → `python risk_report.py`.
Локально: `python risk_report.py --dry-run` (ничего не шлёт и не пишет),
`python risk_report.py --fixtures --no-llm` (офлайн на снимках из `tests/fixtures`).

## Откуда данные

| Что | Источник | Модуль |
|---|---|---|
| Позиции: кошелёк + DeFi, **залог и долг**, health factor | DeBank (страница профиля, 2 эндпоинта) | `risk/positions.py` |
| BTC-адрес Мамы | mempool.space | `risk/positions.py` |
| Режим рынка, уверенность, risk_state, фаза цикла, лестница MVRV | OracAI: `state/last_output.json`, `state/cycle_ladder.json` из публичного репо | `risk/oracai.py` |
| Дневные графики монет портфеля | CoinGecko (`market_chart`, 220 дней) | `risk/market.py` |
| Курсы USDT/USDC, Fear&Greed | CoinGecko, alternative.me | `risk/market.py` |
| Взломы за 30 дней, TVL протоколов | DefiLlama `/hacks`, `/protocols` | `risk/protocols.py` |
| LP: статус хранилища, APR, риски, TVL | Beefy API `/vaults`, `/gov-vaults`, `/apy/breakdown`, `/tvl` | `risk/lp.py` |
| Комментарий + поиск свежих новостей (опц.) | Claude API + web search, секрет `ANTHROPIC_API_KEY` | `risk/llm.py` |

**Почему не `state/history.json`:** старый скрейпер в `main.py` собирает
токены со всех эндпоинтов DeBank подряд (дубли) и не вычитает долг Aave.
Сумма токенов там в ~1.5 раза больше реального баланса. Для оценки долей это
непригодно, поэтому риск-отчёт снимает позиции сам. Проверка: чистая сумма
позиций должна сходиться с итогом DeBank (±5%), иначе в отчёте предупреждение.

## Категории рисков (светофор)

Категория горит цветом худшего флага. Сводного «скора» нет намеренно.

| Категория | 🔴 | 🟡 |
|---|---|---|
| Системный | OracAI RISK_OFF при уверенности ≥40%, хвостовой риск, депег стейбла ≥2% | BEAR при уверенности ≥40%, OracAI старше 48ч, депег ≥0.5%, F&G ≤15/≥85 |
| Плечо и ликвидации | HF < 1.5 (правило: гасить) или ликвидация при падении < 30% | HF 1.5–1.6, ликвидация при падении < 45%, плечо ≥ 1.5× |
| Протоколы и взломы | взлом нашего протокола/эмитента за 30д, отток TVL ≤ −40% за 7д | отток TVL ≤ −20%, > 50% кошелька в одном протоколе |
| LP и доходность | хранилище Beefy eol/paused (доход 0%) | нет аудита / не верифицирован, TVL хранилища < $50k, наша доля > 10%, APR > 100%, IL > APR |
| Контрагенты обёрток | один кастодиан (BitGo, Binance, Tether…) ≥ 50% активов | ≥ 30% |
| Диверсификация | альткоины (класс) ≥ 40% | альткоины ≥ 30%, BTC > 75%, стейблов < 5%, акций > 5%, вне белого списка ≥ 5% |
| Тренды | — | актив ≥10% портфеля в нисходящем тренде, −25% за 30д, BTC ниже SMA200 |

**«Ликвидация при падении на X%»** — на сколько должны синхронно упасть все
волатильные активы позиции, чтобы HF стал 1. Порог ликвидации выводится из
текущего HF (`lt = HF·D/C`), стейблы в залоге и долге не падают. Формула и
тесты — `risk/exposure.py::liquidation_drop`.

## LP-позиции

Позиция DeBank сопоставляется с хранилищем Beefy по адресу контракта
(`pool.id` = `earnContractAddress`, ищем и в `/vaults`, и в `/gov-vaults`).

- **APR** — простой: сумма компонент `/apy/breakdown`. `totalApy` Beefy с
  ежедневным реинвестом на волатильных CLM-парах даёт 1000%+ и как ожидание
  дохода не используется.
- **IL** — нижняя оценка для полного диапазона: `σ²/8` в год, σ — годовая
  волатильность отношения цен пары за 30 дней. Beefy CLM и Uniswap V3 —
  концентрированная ликвидность, реальные потери больше. Для пар с
  токенизированными акциями графика нет — IL не оценивается.
- Хранилище **eol/paused** — стратегия выключена, доход 0%: первым пунктом
  ребалансировки «вывести».

## Ребалансировка

Только предложения. Порядок:
0. **Вывести** из закрытых хранилищ Beefy (eol/paused).
1. **Займы: держим HF ≥ 1.5** (правило владельца). Ниже — погасить часть
   долга до HF 1.65 (запас, чтобы не гасить каждую неделю). Отчёт даёт две
   суммы: стейблами с кошелька (`R = D − lt·C/T`) или выводом залога.
   Проверка раз в неделю не защищает от обвала внутри недели: HF 1.5 при
   залоге в крипте и долге в стейблах — это ликвидация при падении на ~33%.
2. **Точечные лимиты**: всё вне белого списка, акции > 5%.
3. **Классы к цели** с полосой ±5 п.п. и минимальной сделкой $50.

**Альткоины — один класс.** Лимита на отдельную монету нет: альты движутся
вместе, важна их суммарная доля. Докупка альтов — поровну в 2 сильнейших
монеты белого списка; продажа — начиная с самых слабых из тех, что уже есть.
Сила = среднее доходностей за 30 и 90 дней по дневным графикам CoinGecko;
монеты в нисходящем тренде (цена < SMA50 < SMA200) уходят в конец рейтинга.
Это описание графика, не прогноз. Рейтинг — `risk/market.py::rank_alts`.

Цели и все пороги — в `risk/policy.py`, это единственное место для правки.
Режим OracAI наклоняет цель по стейблам (BEAR/RISK_OFF: +10 п.п.,
BULL/RISK_ON: −5 п.п.) **только** если уверенность OracAI ≥ 40% и данные
свежие — собственный confidence gate OracAI уважается.
